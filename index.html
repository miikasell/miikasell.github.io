Merge Resort Island 2026 · closed alpha

My own merge game for Android, in Google Play closed testing. Solo project: code, tools and the procedural art pipeline.

Place tiles on a small hex island, merge three of a kind into something bigger, and grow a guesthouse into a landmark tower. Pools, dining, fun and relaxation services boost the accommodation around them, so the layout is a calm spatial puzzle. Rearranging is always free and never hurts income: layout drives Appeal, development drives the economy.

Playable build available on request.

What I built and how

Architecture

  • Unity 6 and C#. Game rules and state live in a pure logic layer with no scene dependencies; presentation (map, interaction, UI, audio) sits on top. The same logic runs headless in the tuning simulator.
  • Axial hex coordinates with spiral iteration and fractional-hex picking for touch input.
  • Debug tools in a separate, isolated module that release builds leave out.
  • Live service support for in-game messages, plus analytics, local notifications and separate development and production environments.

Rendering

  • URP with custom HLSL shaders: stylized water and adaptive coastlines that form beaches and lagoons as the island grows.
  • Dual Kawase blur behind UI panels, rendered only while a panel needs it.
  • Low-poly, flat-shaded, vertex-colored art; no textures on tiles.

Tools and content pipeline

  • Over 130 tiles (five accommodation chains of 12–15 levels, four service chains, decorations) generated procedurally by Blender Python scripts with shared palettes and helpers.
  • Custom FBX export add-on, batch preview renders, and an editor step that imports the models.
  • Tile icons baked at edit time instead of runtime render textures, which keeps memory flat and the tile album smooth.

Economy and progression

  • Several goals at different paces: services produce in cycles, the Reception's capacity limits how much a single session earns, and land expansion, daily tasks and a tile-collection album give longer-term goals.
  • A headless tuning simulator plays the real game logic through months of simulated play with several player profiles. It also runs outside Unity on .NET in a few seconds.

Working with Claude Code

  • I direct the design and architecture and set the quality bar; Claude Code handles the implementation across C#, HLSL, Blender Python and tooling, and I review every change.
  • Project rules and design docs keep its work consistent; a coordinator session splits work into parallel feature sessions.
  • It drives the Unity editor and Blender from the command line to build assets, run the simulator and check results, which makes iteration fast for a one-person team.
